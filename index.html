Capstone Project

Grading Diabetic Retinopathy from Retinal Fundus Photographs

We built a system that pairs a CNN classifier with an autoencoder, using the autoencoder as a regularizer to fight overfitting on a small, heavily imbalanced medical imaging dataset. The resulting method was later published at IEEE ICCCA 2020.

The screening bottleneck

Diabetic retinopathy is damage to the retina caused by diabetes. Early on it has no symptoms at all — the only way to catch it is to photograph the retina and look. Left alone, it's a leading cause of preventable blindness.

The catch is that "look" currently means a trained doctor reviewing each fundus photo individually. That doesn't scale: doctors can't be everywhere screening is needed, and every image waits in a queue for one to be free. A model that gives a fast, preliminary severity rating — flagging the images that actually need a doctor's eyes — was the whole motivation for this project.

Data & stack

The dataset

31,631 fundus photos from EyePACS, an open retinopathy-screening platform, each graded 0–4 by a clinician. It's real screening data, not a clean benchmark: different camera models, some images inverted, some out of focus or over/underexposed, a handful mislabeled. A separate 53,576-image set was held out for testing.

  • No DR 22,315 (70.5%)
  • Moderate 5,292 (16.7%)
  • Mild 2,443 (7.7%)
  • Severe 873 (2.8%)
  • Proliferative 708 (2.2%)

70% of the training set is healthy retinas — the class imbalance a plain classifier tends to overfit to. More on that in the results below.

Before training: every image resized to 256×256, randomly flipped horizontally and vertically for augmentation, then normalized to zero mean and unit variance.

How it works

Bigger networks overfit faster on a small dataset, and 31,631 images is small by deep-learning standards. We needed something that forced the network toward features that actually generalize, rather than ones that just memorize the training set.

An autoencoder does exactly that: squeeze the image down to a small bottleneck, then try to rebuild it from just that. The bottleneck can't hold everything, so the network is forced to keep only what matters. We fed that same bottleneck into a small classifier head and trained both objectives — rebuild the image, grade its severity — together. In practice, whatever helps the network rebuild the image well also tends to help it grade the image correctly.

Training procedure

The final model wasn't trained in one pass. It went through three distinct phases over 100 epochs total, each with a different job — the same autoencoder-then-joint-then-freeze idea the earlier single-phase version didn't have yet.

50 epochs
30
20

  1. Learn to see epochs 1–50

    Only the autoencoder trains — encoder and decoder, reconstruction loss only. No classifier yet. The goal is a network that can already compress and rebuild a fundus photo well before it's asked to diagnose anything from that compression.

  2. Learn together epochs 51–80

    The classifier head is attached and everything trains jointly — reconstruction loss and classification loss, summed. This is where the two objectives actually pull on each other.

  3. Specialize epochs 81–100

    The encoder is frozen. Only the classifier keeps training, on classification loss alone — letting it settle into the now-stable features without the joint objective still pulling them around.

Optimization

  • Adam
  • lr = 0.001
  • β₁ = 0.9, β₂ = 0.999
  • dropout = 0.5 (classifier)
  • ReLU hidden activations
